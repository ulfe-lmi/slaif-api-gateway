## Product requirements and design boundaries

R1 Separate default-OFF facility. Explicit operator setting plus absolute operator-owned capture directory outside repository/database and deployed revision setting. Reading a setting alone MUST NOT create an indefinite capture window. Provide small filesystem-local CLI request-capture arm/status/stop/cleanup (or equally clear names documented exactly), arm nextmatchingrequest or finite count with finite absolute expiry; endpoint exactpath and optional VERIFIED authenticated keyUUID filters. Default next1 / expiry5minutes, bounded count/TTL maximums (e.g.100/1hour); no unlimited mode. CLI arming/status/stop should work without HTTP app construction or DB schema; reject malformed options with safe errors. Initial enable/directory/revision config requires process restart; arm/status/stop via shared manifest needs no restart. Exhaustion/expiration survive worker restarts, never automatically rearm. Count claims and storage reservations atomic across the shipped TWO worker processes using ordinary local filesystem locking (fcntl.flock), not per-worker counters. No distributed/NFS/network-filesystem guarantee or coordination framework. Consume claimed attempts even if artifact write fails so failure cannot create endless capture. Expiration checked on every claim; status accurately reports inactive/exhausted/expired and remaining count.

R2 Observe request at ASGI receive boundary BEFORE JSON/model parsing, module normalization or request policy. Preserve original bytes including malformed/unknown fields and formatting, method, raw path, ordered duplicate headers/query parameters and query bytes (lossless encoding allowed). A pureASGI tee is preferred over request.body/BaseHTTPMiddleware rewrites. Forward original receive/send messages unchanged; do not consume/drop/rewrite request data or response streams. If full observation requires bounded buffering/replay, demonstrate unchanged bytes/disconnect/stream/error behavior and do not prebuffer unlimited bodies or block authentication indefinitely. Do not label a body complete unless end-of-body actually observed. Bodies never consumed by app, interruptions, limits or failures must explicitly say incomplete with stable reason and captured/original/declared counts where known; declared Content-Length is not trusted as observed size. Complete requests within shipped normal NGINX client_max_body_size10m MUST be capturable (configure default body budget at least10MiB plus artifact encoding/metadata overhead); no small debug-only cap silently dropping fields. Do NOT add a new request413, body acceptance limit, compressed-body semantics or parser behavior. Capture resource limit affects ONLY capture. If original size unknown, mark unknown, do not invent a count. Raw body representation may be base64 to preserve arbitrary bytes; operator inspection must decode it conveniently. No raw unmasked tempfile, spool or intermediate artifact at any stage. Keep raw content in bounded transient memory only until masked/published; bound concurrent in-flight capture memory by claimed count/storage policy, not arbitrary unlimited workers.
