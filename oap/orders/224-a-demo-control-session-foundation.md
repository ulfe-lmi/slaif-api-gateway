The request record binds a fresh UUID to the fake-admin account UUID and its `credential_generation`, creation/deadline/expiry, a finite state (pending, claimed/running, verified-unpublished, failed, cleanup pending/cleaned or a comparably small reviewed vocabulary), safe finite failure code, and an optional exact worker job/copy identity once independently verified. The session record stores only a HASH of a cryptographically random opaque browser token, the account/generation, exactly one verified request/copy binding, creation/expiry/revocation times and only metadata needed for later CSRF/session operation. A session must never be issuable for a pending, failed, expired, wrong-account, wrong-generation, or reused copy. No live `admin_users`/`admin_sessions` row is an authentication authority for fake admins.
3. Implement an explicit transactional state machine in `app/slaif_gateway/services/demo_web_control.py` and a small repository: create one request after checking enabled account/current generation, claim one pending request exactly once with PostgreSQL row locking and a bounded lease/deadline, record a worker-only verified handoff only when exact request/job/account/generation binding and a verified 223 manifest state agree, fail safely, create one session only for the exact verified request, validate that active count is nonzero and account remains enabled with matching generation on EVERY later validation, revoke idempotently and mark cleanup pending.
