## Executive summary

The three pre-round trust gaps named by the order — an INTACT supplied bundle claiming this invocation fetched sources, a stale stage line claiming a retrieval that never happened, and a package-version-only code identity that two different `collection.py` byte sets shared — are closed by one bounded delta confined to the catalog-refresh reporting/trust surface (no transport redesign, no new attestation platform, no sandbox/downloader, no environment or Git inspection):

1. **I1 — the execution path selects the acquisition scope, never the bundle JSON.** A runner-selected acquisition argument (`live_collection` / `offline_supplied`) is passed separately from the untrusted proposal: only the actual `collect` command selects live, and only after its collection path executed; `review` and pure validation default offline even with an intact or fabricated `collection`/tool/capture. The report scope now has three truthful values — `live_collection` (this invocation acquired), `supplied_collection` (historical provenance in a supplied bundle, re-verified offline), `offline_replay` (no collection identity) — with matching first-screen subtitle, source-evidence lines, footer scope, and CLI `stage`. Collect failures are labeled by the path actually reached: `collection not started` (baseline failure before any retrieval), `collection attempted and failed before completion` (failed retrieval attempt), and the `live collection` wording only after a completed collection (semantic blockers, post-collection baseline identity mismatch); the JSON summary and the published report footer carry the same reached-path stage (including through the shared `_blocked_identity` publisher). Completed collects keep the live label; the honest absent apply/Codex limitation wording is retained. No CLI flag or JSON field can promote supplied bytes to actual HTTP.
2. **I2 — the original context is authenticated and replayed offline.** Each sealed run's `validation.json` now carries a runner-owned `execution_context` inside the HMAC-protected content: the runner-selected `acquisition` mode, the measured `generator` identity (tool + `code_revision`), and `generator_versions` bound by `Literal` to the running code's own schema/renderer/policy/extractor constants. `verify` checks content digests, then the HMAC, then the context shape/version, and only then replays the validation with the ORIGINAL authenticated context — no HTTP/DNS/SQL, no key creation/rewrite/reseal — and reports the `original generator` (authenticated in the sealed `validation.json`) separately from the `current generator` (measured at verification time). A forged mode/tool identity fails at HMAC (digests still ok, hmac fails); a resealed unsupported context shape/version is refused explicitly (`unsupported context shape or version`), and a pre-context legacy sealed run is refused explicitly (`missing (unsupported legacy validation context)`) — no historical renderer fleet, no re-derivation, no archive mutation. The generator fallback is live-gated: a fabricated supplied `collection` identity can never become the current generator of an offline review.
3. **I3 — bounded measured tool identity.** New `execution_identity.py` (single small helper, included in its own measured set) computes `catalog-ccid/v1:sha256:<64 hex>` over the (logical name, content) pairs of a FIXED set of 15 owned catalog-refresh files, with fail-closed bounds (32 files, 512 KiB/file, 8 MiB aggregate) and a one-byte EOF growth probe. It is honest about what it is: source-content identity of exactly that set — not a whole-environment digest, not loaded-bytecode attestation, not a security boundary, not a reproducibility promise. Relocation/timestamp changes do not change it; changed bytes do, even under an unchanged package version; unavailable/unsupported input yields the explicit `unavailable` marker, never a fabricated known-current identity. No Git inspection, no environment/config traversal, no subprocess, no recursive scan. The package version stays separately in the existing tool metadata.
4. **I4 — targeted offline browser proof.** The browser suite now drives an ACTUAL mocked `collect` (both providers, HTTP/DNS refused) and an INTACT supplied-collection case with explicit runner-selected scopes, asserting the scope labels, tool identity, retrieval records, and `NOT_RUN` researcher state in first-screen/expanded text, at 1440×900 first screen, 1440 expanded, 1280×800 and 375×812 (collapsed and expanded), JavaScript disabled, exactly one document request, font floors, and real print PDFs for the price/FX cases — all offline.
