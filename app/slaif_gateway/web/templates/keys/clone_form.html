Validity

Times are UTC. Choose exactly one mode and fill in only that mode's fields; the other modes' fields must stay blank.

Duration mode: a positive whole number of seconds, minutes, hours, or days (stored as exact seconds; maximum {{ max_duration_seconds | num }} seconds, about 1,000 years). The window starts at EXECUTION time, so the preview shown on the review page is an estimate, not a promise.

Absolute mode: both UTC times are required; the end must be after the start and still in the future when the clone executes.

Copy-source-expiry mode takes no extra values: the new key becomes valid from execution time until the source's CURRENT expiry, which the core rechecks against the live source at execution.

One-Time Key Delivery

The selected channel is bound into the review you are about to confirm. Changing it later requires a new review - applying never changes this choice.

Send-now and enqueue suppress the browser display and dispatch only AFTER the clone is committed. A post-commit dispatch failure never requires a second clone: the pending delivery keeps its stable ID and can be retried through the existing one-time sendability flow.
