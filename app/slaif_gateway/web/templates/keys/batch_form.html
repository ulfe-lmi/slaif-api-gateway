Persisted status scope

The scope is the PERSISTED status (active/suspended/revoked), not expiry: an active key whose validity window has passed stays in scope as active, and the review page re-checks it at execution. At least one status is required; the default is active only.

Cohort scope is filtered in the database by the selected statuses; members excluded by status are NOT enumerated on the review page. Explicit UUID scope reports each actual excluded key and its status on the review page.

Input Mode

Choose ONE input source for the policy change: the guided controls, or the advanced strict version-1 configuration document. The other source's fields must stay at their defaults/blank.

The document is the same strict version-1 key configuration the CLI accepts: schema_version 1 plus any subset of the supported fields. Omission = unchanged, explicit null = clear (unlimited/inherit/remove depending on the field), zero = zero. An empty provider list is deny all; an empty model or endpoint list alone is NOT deny-all while the separate allow-all flag is retained (allow-all is the flag set with an empty list). Complete policy blocks are replacements where the core says so. Guided mode leaves this document blank; advanced mode leaves every guided policy control at its default.

Policy Changes (guided)

The guided controls compose ONE partial strict version-1 configuration document that is applied to EVERY selected key, independently per target. At least one change is required. "Leave unchanged" omits the field (preserved); "Clear" sends explicit null; a value is only used with "Set".

Lifetime quotas (PostgreSQL hard limits)

Clear (null) means UNLIMITED for that lifetime quota; setting 0 means a ZERO limit; leave unchanged preserves the key's current value. Values are finite numbers of zero or more (cost: decimal EUR; tokens/requests: whole numbers).

Rate limits (Redis counters, per selected window)

Counts are positive whole numbers per the key's SELECTED window (the window member is part of the same policy). An omitted member is preserved; a cleared member (null) inherits the deployment; clearing all four members clears the whole block. Redis rate limiting only enforces while ENABLE_REDIS_RATE_LIMITS is true.

Allow lists take one entry per line (or comma-separated), up to 100 entries of 256 characters (the searchable picker keeps the full selection even beyond its latest-100 display batch). Providers: null = unrestricted, empty list = deny all. Models/endpoints: "allow all" sets the allow-all flag with an empty list; "deny all" sends an explicit empty list; an allow list also clears the allow-all flag. At execution the shared configuration validators re-check the resulting configuration per key (validation of stored policy, not an inference test; admission, pricing, and provider health are checked separately when a request is made); a resulting state the validators refuse rejects the whole batch with zero writes.

Lazy throttling (wait for capacity)

Reject replaces the stored policy with reject mode; wait needs BOTH positive whole-number values; remove sends explicit null (the deployment default applies again).

Chat streaming live-burn (streaming chat surface only)

A complete block with the installation's bounded margins is sent for enable/disable; blank margins take the surface defaults. The change applies only to the chat streaming surface with streaming; final provider usage/cost remains authoritative.
