for exact `mcp__codex_worktrees`. Its declarations were `create_worktree`,
`get_worktree_creation_status`, and `list_worktrees`, all ordinary functions.
No request body, history, credentials, key identity or raw response identifier
is included in this report or the fixture. The finite capture was exhausted,
stopped and cleaned; both stored artifacts were deleted and the facility was
disabled again before this preset follow-up.

The initial isolated client qualification omitted this built-in namespace.
It therefore did not establish ordinary TUI worktree-declaration compatibility.
A fresh installation can advertise these tools: pinned upstream
`codex-rs/features/src/lib.rs` marks `worktrees` as `Stage::Removed`, and
`codex-rs/tui/src/app_server_session.rs::start_dynamic_tool_mcp` checks local
workspace/trust/storage support rather than that feature flag. Consequently
`[features] worktrees = false` does not suppress the declaration in 0.164.0.

connector prefixes, identifier grammars, custom types and all ceilings remain

`c5261aa3c40353889e86a3c87cb8ca3e53da3435e1654c5250b296e4347259a1`.
